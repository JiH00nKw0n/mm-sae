# CC3M에서 학습한 SAE의 대응 비교

CC3M으로 SAE와 대응을 학습한 뒤, 기존 실험과 같은 COCO 2017 검증 이미지 5,000장에서 검색 성능을 비교한다. CC3M 학습 설정에서 평균 제거와 다대다 대응의 효과가 유지되는지 확인하는 실험이다. 원논문의 COCO Karpathy test 분할을 재현하는 실험은 아니다.

## 학습과 평가 조건

- CC3M은 `pixparse/cc3m-wds`의 `46f3d69f840e59d77d52e8decfe5baec97e94c7f` 버전을 사용한다. 학습용 압축 파일 576개를 순서대로 처리한다. 예상 표본은 약 290만 쌍이며, 실제 사용한 수와 읽을 수 없었던 표본은 저장된 기록에서 확인한다.
- CLIP ViT-B/32는 고정한다. 이미지와 텍스트 임베딩은 각각 길이가 1이 되도록 정규화한다. 텍스트는 기존 실험과 동일하게 최대 77토큰을 입력한다.
- 이미지 SAE와 텍스트 SAE는 각각 특징 4,096개를 사용하고 입력마다 상위 32개를 활성화한다. 모달리티 간 정렬 손실을 사용하지 않는다. 두 복원 손실의 평균으로 두 모델을 함께 갱신하지만 모델 파라미터는 공유하지 않는다.
- 원논문의 주요 학습 설정인 10회 학습, 배치 1,024, 학습률 0.0005, AdamW, 가중치 감쇠 0.00001, 코사인 학습률 조정, 초기 5%의 학습률 증가, 전체 기울기 길이 제한 1을 사용한다. 첫 실행의 난수 초기값은 0이다.
- 기존 COCO 실험은 상위 8개 활성화와 30회 학습을 사용했다. 따라서 이번 실행과 기존 실행의 차이를 학습 데이터만의 효과라고 해석하지 않는다.
- 대응 방법을 맞추고 설정을 선택하는 자료는 CC3M에서 이미지 단위로 80%와 20%로 나눈다. 기존 비교와 같은 후보 설정을 사용한다. 최종 COCO 검색 결과로 설정을 선택하지 않는다.
- 검색 평가는 기존 COCO 2017 검증 자료 전체를 유지한다. 이미지로 캡션을 찾는 방향과 캡션으로 이미지를 찾는 방향에서 정답이 상위 1개, 5개, 10개 안에 포함되는 비율을 계산한다.

## 비교 내용

1. 원래 활성값, 학습 자료의 평균을 뺀 활성값, 평균을 빼고 표준편차로 나눈 활성값에서 각 대응 방법을 비교한다.
2. 헝가리안 일대일 대응, 각 특징의 최고점 또는 상위 점수 연결, Sinkhorn 가중 대응, 연결 수를 제한한 다대다 대응, 희소한 가중 대응, 작은 특징 집합을 이용한 대응을 비교한다.
3. CCA와 Procrustes를 포함한다. 같은 공통 공간 차원에서 모달리티 내부의 상관 보정 효과를 구분하고, 특징 집합의 좌표끼리 직접 비교하는 조건도 계산한다.

이번 비교는 검색 성능을 평가한다. CC3M에 COCO 범주 주석이 있다고 가정하거나 객체 제거 실험을 추가하지 않는다.

## 실행과 진행 상황

서버에서는 `/mnt/working/mm-sae`에서 다음 명령을 실행한다. 많은 임베딩 파일을 동시에 읽을 수 있도록 파일 수 제한을 높인다.

```bash
ulimit -n 4096
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  .venv/bin/python -u -m experiments.paired_corpus.run \
  --config configs/cc3m-server.yaml
```

실제 데이터 128쌍을 사용하는 소규모 검증은 `/mnt/working/mm-sae/configs/cc3m-smoke-server.yaml`로 실행한다. 작은 SAE를 두 단계 학습하고 COCO 이미지 32장으로 결과 생성까지 검증하므로 성능 결과로 해석하지 않는다.

진행 상황은 다음 파일에 저장된다.

- `/mnt/working/mm-sae/runs/cc3m-sae-2026-10-04/progress.json`은 전체 단계와 현재 작업을 기록한다.
- `/mnt/working/mm-sae/cache/cc3m-clip-b32/embedding_progress.json`은 처리한 쌍 수, 처리 속도, 임베딩 추출의 예상 남은 시간을 기록한다.
- `/mnt/working/mm-sae/runs/cc3m-sae-2026-10-04/run.log`는 학습과 후속 비교의 출력을 기록한다.
- `/mnt/working/mm-sae/runs/mapping-suite-cc3m-2026-10-04/progress.json`은 대응 방법의 설정별 처리 상황을 기록한다.
- `/mnt/working/mm-sae/runs/mapping-ablation-cc3m-2026-10-04/progress.json`은 입력 보정과 공통 공간 및 집합 비교 상황을 기록한다.

원본 압축 파일은 한 개씩만 임시 저장하고, 그 파일의 임베딩 저장을 마치면 삭제한다. 완료한 임베딩 파일과 학습 체크포인트를 재사용하므로 같은 설정으로 다시 실행하면 완료한 부분부터 이어간다. 입력 자료나 학습 설정이 달라졌다면 별도의 결과 폴더를 사용한다. 활성값 생성 코드를 변경한 경우에도 별도의 결과 폴더를 사용한다.

## 실행 전 확인

CC3M 2,048쌍을 임시 저장한 파일에서 처리하는 데 약 31.7초가 걸렸다. 첫 압축 파일을 내려받는 데 약 14.3초가 걸렸다. 이 측정치를 전체로 환산하면 임베딩 추출에 약 14.8시간이 필요하다. 이는 처음 파일에서 측정한 추정이며, 파일별 읽기 속도에 따라 달라진다. 전체 20–36시간은 후속 대응 계산을 포함한 잠정 범위이고, 전체 작업을 실측한 값은 아니다.

실제 CC3M 128쌍으로 임베딩 추출, HF Trainer 학습, 새 SAE로 COCO 활성값 생성, 대응 비교, 입력 보정 비교, HTML 보고서 생성까지 확인했다. 완료한 소규모 실행의 재사용도 확인했다. 새 모듈과 연결부의 테스트 77개, Ruff, Pyright 검사를 통과했다.
