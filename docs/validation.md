# 실행 확인 기록

2026년 9월 14일에 실제 COCO 자료를 사용하는 소규모 실행과 자동 검사를 수행했다. 전체 COCO 학습이나 전체 규모의 객체 제거 실험은 수행하지 않았다. 이 기록은 코드의 실행 여부를 확인한 것이며 RQ1 가설의 실험 결과가 아니다.

실제 자료 점검은 macOS ARM의 Python 3.11 환경과 Linux ARM의 CPU Docker 컨테이너에서 수행했다. `smoke-real.yaml`로 학습 이미지 4장과 캡션 20개, 검증 이미지 2장과 캡션 10개를 읽었다. 이미지는 식별자 순으로 선택했으며 학습 이미지 식별자는 9, 25, 30, 34이고 검증 이미지 식별자는 139, 285다.

공식 캡션 JSON에서 전체 원본 자료의 이미지·캡션 수도 확인했다. 학습 분할은 이미지 118,287장과 캡션 591,753개, 검증 분할은 이미지 5,000장과 캡션 25,014개였다. 모델 입력에는 소규모 설정에서 선택한 행만 사용했다.

고정된 공개 CLIP ViT-B/32를 실행하고 이미지·텍스트 SAE를 각각 2단계 학습했다. SAE는 각각 64개 특징 중 최대 8개를 활성화하는 소규모 구조였다. 데이터 준비부터 보고서 생성까지 아홉 단계가 종료 상태 0으로 끝났다. 원본 활성값 외에 개념별 이미지 가림 입력 44개와 문장 삭제 입력 50개를 실제 모델로 계산했다. 동일 이미지나 캡션에 서로 다른 개념을 제거한 경우는 각각의 편집 입력으로 센 개수다.

세 그림의 PNG와 PDF, 원본 전체 상관행렬, 원본·편집 활성값, 대표 선택 AUROC, 두 연결 방식의 배정과 판정 결과를 저장했다. PNG 그림의 글자와 축이 잘리지 않는지도 확인했다.

이 소규모 자료에서는 대표 특징의 중복 때문에 두 연결 방식의 평가 행이 모두 판정 불가였다. 세 번째 실험의 검사 가능한 원본 오류는 0개였으며, 결과와 그림에 이를 명시했다. 따라서 실제 COCO 점검으로 연결 회복 효과가 확인된 것은 아니다.

연결 회복 계산은 별도의 인공 활성값 검사로 확인했다. 100행에서 두 객체의 동시 등장 확률을 정하고 잘못된 상관이 큰 상황을 만들었다. 30개 입력에서 조건부 제거를 수행해 표지 상관이 0이 되는지, 두 연결 방식을 실제로 다시 계산하는지, 삭제한 이미지·문장 수가 일치하는지 검사했다. 이 자료는 동작 검사용이며 COCO 측정 결과에 합치지 않았다.

자동 테스트 16개가 통과했다. 검사 범위에는 0 활성값의 동점을 포함한 정확한 AUROC, 상수 특징의 상관 미정의 처리, Greedy의 상대 재사용과 헝가리안의 일대일 제약, 문장 표현 겹침, 학습 자료의 이미지·캡션 행 수 차이, 모델 저장·복원, 입력 내용에 따른 표현 재사용, 중단된 표현 추출과 객체 제거 검사의 재개가 포함된다. `ruff check`도 통과했다.

CPU Docker 이미지를 실제로 빌드했으며 설치된 의존성의 충돌이 없음을 `pip check`로 확인했다. Docker 실행에서는 앞서 내려받은 COCO 자료와 CLIP 가중치를 연결했고, `HF_HUB_OFFLINE=1`로 추가 모델 다운로드 없이 실행했다. 최초 빌드의 의존성 다운로드는 네트워크 시간 초과로 한 차례 실패했으며 다운로드 제한 시간을 늘린 뒤 성공했다.

NVIDIA GPU용 Docker 대상과 전체 COCO 설정은 준비했지만 GPU 서버에서 빌드·실행하지 않았다. 전체 규모의 처리 시간, 메모리 사용량과 학습 성능은 아직 확인하지 않았다. 캡션의 자동 표현 주석도 사람 검토를 완료한 의미 정답이 아니다.

실행의 설정·코드 지문은 각 결과 폴더의 `run.json`, 실제 라이브러리 버전은 `environment.json`, 단계 종료 여부는 `completed` 폴더에 남는다. 기본 Docker 결과 위치는 `/workspace/runs/smoke-real`이며 전체 실험의 결과와 구분한다.
