# 전체 실행 전 확인할 RQ1 설정

**전체 실험은 아직 시작하지 않았다. 아래는 현재 코드가 실행할 안이며, 사용자의 승인을 받은 뒤 실행한다.** 연구 질문은 이미지와 텍스트 특징의 동시 활성화 상관계수가 객체 대응을 반영하는지, 함께 등장하는 다른 객체 때문에 실제 연결이 틀리는지를 확인하는 것이다. 현재 구현은 이 질문을 객체별 대표 특징에서 진단한다. 모든 SAE 특징의 의미 정답을 확보한 실험은 아니다.

실행할 설정은 서버의 `/mnt/working/mm-sae/configs/elice.yaml`이다. 결과는 `/mnt/working/mm-sae/runs/elice-rq1`에 저장한다. 이 문서, 코드, 해석된 설정, 주요 설치 패키지 버전의 파일 지문을 승인 기록과 대조한다. 어느 하나라도 달라지면 이 설정으로 실험을 시작할 수 없다. 현재 승인 기록은 없다.

**학습 설정은 이미지별 한 번, 캡션별 한 번을 사용한다.** 희소 오토인코더(SAE)는 입력 벡터를 소수의 활성 특징으로 표현하고 입력을 복원하도록 학습하는 모델이다. 이미지 SAE와 텍스트 SAE는 별도 모델이며 각각 학습한다.

| 항목 | 실제 실행할 값 |
| --- | --- |
| 학습 자료 | 공식 COCO2017 학습 이미지 118,287장과 캡션 591,753개를 모두 사용한다. 이미지 수나 학습 단계 수를 제한하지 않는다. |
| 두 모델의 학습 행 | 이미지 SAE는 이미지 118,287행을, 텍스트 SAE는 캡션 591,753행을 매 학습 회차에 사용한다. 캡션이 정확히 5개라는 가정은 하지 않는다. |
| 입력 표현 | Hugging Face `CLIPModel`과 `CLIPProcessor`의 `openai/clip-vit-base-patch32`를 사용한다. 리비전은 `3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268`로 고정한다. 투영 벡터를 float32로 길이 정규화한다. |
| SAE 구조 | 양쪽 각각 특징 4,096개를 만들고 활성값이 큰 최대 8개만 남긴다. 디코더 특징 벡터는 매 갱신 뒤 길이를 정규화한다. 죽은 특징을 위한 추가 보조 손실은 사용하지 않는다. |
| 학습 담당 | Hugging Face `Trainer`와 `datasets.Dataset`을 사용한다. 기존 코드의 SAE 정의를 참고했다. |
| 학습 횟수와 묶음 | 각각 30회 전체 자료를 학습한다. 한 묶음은 1,024행이며 마지막 불완전 묶음도 사용한다. 단일 GPU에서 이미지 3,480회, 텍스트 17,340회 갱신한다. |
| 최적화 | `adamw_torch`를 사용한다. 학습률은 0.0005, 가중치 감쇠는 0.00001, 두 모멘텀 계수는 0.9와 0.999, 안정화 상수는 0.00000001이다. 최대 기울기 크기는 1이다. |
| 학습률과 재현성 | 처음 5%의 갱신 동안 학습률을 올린 뒤 코사인 함수로 줄인다. 모델과 자료 순서의 시드는 0이다. 모델 학습은 한 시드만 수행한다. |
| 저장 | 학습 상태를 매 회차 저장하며 최근 2개를 유지한다. 추출한 CLIP 표현은 여러 실험에서 재사용한다. |
| 분석 자료 | 대표 선택과 원본 상관행렬에는 `train2017`을 사용한다. `val2017`의 이미지 5,000장과 캡션 25,014개에서는 선택한 대표의 제거 반응만 평가한다. 검증 자료로 대표를 다시 고르거나 짝짓기 성능을 측정하지 않는다. |

학습 인자의 값은 참조 연구의 COCO 설정에 맞췄다. 다만 참조 연구는 Karpathy 학습 분할의 이미지 113,287장과 캡션마다 반복한 이미지 행을 사용했다. 이번 공식 COCO2017 분할과 이미지별 한 행은 사용자가 요청한 변경이다. 따라서 이미지 학습의 자료 가중치와 갱신 횟수까지 선행 연구와 동일하다고 쓰지 않는다.

**이미지 주석의 기준은 CLIP이 실제로 보는 중앙 영역이다.** COCO-Stuff의 80개 객체 범주와 91개 배경 범주, 합계 171개를 대상으로 한다. 정수 PNG 주석에 CLIP과 같은 크기 조정과 중앙 자르기를 적용하고, 그 영역 안에 범주가 있으면 존재 표지를 1로 둔다. 전체 원본 이미지에 있다는 이유만으로 잘려 나간 객체를 존재한다고 세지 않는다. 전체 이미지 기준 표지도 저장하지만 현재 그림의 기본 기준은 `label_scope: model_input`이다.

텍스트에는 COCO-Stuff가 제공하는 객체 표현 정답이 없다. 현재는 캡션에서 범주명과 등록한 동의어를 단어 경계 규칙으로 찾아 표지와 삭제 범위를 만든다. 이미지 표지를 캡션에 복사하지 않는다. 이 표지는 자동 주석이며 사람이 확인한 의미 정답이 아니다. 표현을 삭제한 뒤 띄어쓰기는 정리하지만 문법을 다시 쓰지는 않는다. 사람이 검토한 캡션 주석 파일을 입력하는 기능은 있으나 현재 설정에는 지정하지 않았다.

**각 객체의 대표 특징은 원본과 해당 객체 제거본을 구별하는 AUROC가 가장 큰 특징 하나다.** AUROC는 원본 활성값 하나가 제거본 활성값 하나보다 높을 확률을 순위로 계산한 값이며, 동점은 0.5로 센다. 객체 c가 있는 이미지 N장의 원본 활성값 N개와 같은 이미지에서 c의 모든 주석 영역을 흰색 RGB(255, 255, 255)으로 채운 활성값 N개를 비교한다. N²개의 원본·제거본 교차 비교에 해당하는 표준 AUROC이며, 같은 이미지에서 감소한 비율과는 다르다. 텍스트도 c의 모든 명시적 표현을 삭제해 같은 방법으로 계산한다.

원본 상관 계산 자료에서 한 번이라도 켜진 특징 중 최대 AUROC를 고른다. AUROC 0.8 같은 문턱을 넣지 않는다. 동점이면 번호가 가장 작은 특징을 고르고 동점 수를 저장한다. 원본·제거 쌍이 없으면 대표가 없다고 기록한다. 여러 객체가 같은 대표를 고를 수 있으므로 대표의 공유 여부와 선택·검증 AUROC를 함께 저장한다. 최고 AUROC가 낮아도 임의로 다른 기준을 적용하거나 객체를 제외하지 않는다.

**원본 특징 상관행렬은 전체 이미지 특징과 텍스트 특징 사이의 부호 있는 피어슨 상관계수다.** 각 캡션에 해당 이미지의 활성값을 붙인 591,753개 행에서 계산한다. 행렬 크기는 4,096 × 4,096이다. 이미지 학습에서 한 번 사용한 이미지도 상관 계산에서는 캡션 수만큼 반복된다. 상수 특징의 상관계수는 미정의라고 별도로 표시한다.

미정의 점수는 연결 최적화에서 제외한다. 원본 후보 특징의 번호는 고정하지만, 제거 후 상수가 된 특징에는 유효한 연결이 없다. 상수가 된 이미지 대표는 상관 미정의로 평가 분모에 남긴다. 미정의 값의 저장용 0을 실제 상관 0으로 취급하지 않는다.

**본문 그림은 3개, 본문 표는 0개로 구성한다.** 아래 예상은 가설이 맞을 때 지지받을 방향이며 실제 결과가 아니다. 반복별 수치와 전체 조합은 CSV·JSON으로 보존한다. 대표 특징 품질을 위한 CSV는 생성하지만 출판용 부록 표는 아직 자동 생성하지 않는다.

| 그림 | 실제 계산과 표시 | 무엇을 주장할 수 있는가 |
| --- | --- | --- |
| 그림 1은 주석 상관과 특징 상관을 비교한다. | 이미지에서 객체 a와 b의 이진 존재 표지로 피어슨 상관을 구한다. 이미지 대표 i(a)와 텍스트 대표 j(b)가 있는 모든 순서 있는 조합을 사용하고 a=b만 제외한다. 최대 29,070개 조합이며 구간별로 추출하지 않는다. 주석 상관을 −1부터 1까지 0.2 간격으로 나누고 각 구간의 특징 상관 C[i(a),j(b)] 평균, 모집단 표준편차, 조합 수를 점과 오차 막대로 표시한다. | 주석상 자주 함께 등장하는 서로 다른 객체가 높은 특징 점수를 받는지 확인한다. 오른쪽 구간에서 점수가 높아지는 것이 예상 방향이다. 같은 객체를 제외한 그림이므로 의미 대응 분류 정확도나 AUROC를 주장하지 않는다. 표준편차는 신뢰구간이 아니다. |
| 그림 2는 실제 연결의 판정 비율을 비교한다. | 원본에서 활성화된 전체 특징에 Greedy와 헝가리안 알고리즘을 각각 적용한다. Greedy는 이미지 특징별 최고점 하나를 고르며 텍스트 특징의 중복 선택을 허용한다. 헝가리안은 전체 점수 합을 최대화하는 일대일 연결을 고른다. 평가 분모는 대표로 선택된 고유 이미지 특징 수다. 같은 객체, 다른 객체, 판정 불가, 상관 미정의, 미연결을 누적 막대로 표시한다. | 높은 다른 객체 점수가 실제 오연결로 이어지는지 확인한다. 두 방식 모두 다른 객체의 단일 대표를 선택한 사례가 나오는 것이 오류 가설의 예상이다. 어느 방식이 더 우수하다고 미리 가정하지 않는다. 전체 4,096개 특징의 의미 정확도는 아니다. |
| 그림 3은 객체 제거 후 변화를 4개 부분으로 보여준다. | 원본, 같은 양의 무작위 제거, 동시 등장 관계를 약화하는 제거를 비교한다. 같은 객체 상대와 원래 오연결 상대의 평균 점수, 원래 오류의 회복률, 기존 올바른 연결의 손상률, 편집 이미지당 꺼진 특징 수를 표시한다. | 조건부 제거에서 잘못된 점수가 더 낮아지고 오류가 더 자주 회복되며 기존 정답이 유지되는지 본다. 이 결과는 일부 오류에 입력상의 객체 관계가 기여한다는 해석을 지지한다. 한 번의 편집 자료로 모든 오류를 고친 성능을 뜻하지 않는다. |

그림 1의 주석 상관은 이미지 a 존재와 이미지 b 존재 사이의 상관이다. 이미지 a 존재와 캡션 b 언급 사이의 상관도 CSV에 저장하지만 현재 그림의 가로축에는 쓰지 않는다. a=b 제외는 같은 객체 제외이며, 우연히 여러 객체의 대표가 같은 특징 번호여도 그 조합을 삭제한다는 뜻은 아니다. 구간은 왼쪽 경계를 포함하고 오른쪽 경계를 제외하며 마지막 구간만 1을 포함한다.

그림 2의 정답 판정은 양쪽 특징이 각각 정확히 한 객체의 대표인 경우에만 가능하다. 둘의 객체가 같으면 일치, 다르면 불일치다. 여러 객체가 공유한 대표나 대표가 아닌 텍스트 특징으로 연결되면 판정 불가다. 판정 불가가 많으면 대표 기반으로 확인한 오류가 제한적이라는 결과를 그대로 보고한다. 판정 불가를 오답이나 정답으로 바꾸지 않는다.

**그림 3은 실제 오연결을 대상으로 같은 객체의 제거 양을 맞춰 비교한다.** Greedy 또는 헝가리안에서 이미지 객체 a의 대표가 다른 객체 b의 텍스트 대표에 연결된 모든 (a,b)의 합집합을 사용한다. a가 있을 때 b가 있는 비율을 p1, a가 없을 때 b가 있는 비율을 p0로 둔다. p1>p0>0이면 a와 b가 함께 있는 이미지의 q=1−p0/p1 비율에서 b만 제거한다. 제거 수는 가장 가까운 정수로 반올림하고 정확한 중간값은 짝수 쪽으로 정한다. 예를 들어 p1=0.8, p0=0.2이면 동시 등장 이미지의 75%에서 b를 지운다. 달성한 존재 비율과 상관은 실제 편집 표지에서 다시 계산한다.

무작위 대조는 b가 있는 전체 이미지에서 b를 제거한다. 조건부 제거와 이미지 수, 편집한 캡션 수를 정확히 맞추고 가림 면적은 5개 분위 구간 안에서 맞춘다. 선택한 이미지의 캡션에서 b를 언급한 모든 표현을 삭제하며, b가 없는 캡션은 유지한다. 두 조건의 실제 면적 차이와 겹친 이미지 수도 기록한다. p0=0이거나 가능한 편집 수가 부족한 사례는 이유를 남겨 제외한다. 원래 오류 목록에서는 삭제하지 않는다.

오류 조합별로 두 제거 조건을 5회씩 반복한다. 각 편집 자료의 전체 상관행렬과 두 연결 방식을 다시 계산한다. CLIP과 SAE는 재학습하지 않으며 대표 특징 번호와 원본 연결 후보 집합도 고정한다. 꺼진 특징 수는 원본에서 양수였고 편집 후 0인 특징의 수다. 새로 켜진 특징과 연속 활성값의 변화도 저장한다. 판정 불가로 바뀐 오연결은 회복으로 세지 않는다. 기존 정답이 새 오답이 된 경우와 판정 불가가 된 경우를 구분해 저장하고 그림의 손상률에서는 둘을 합친다.

각 오류 조합마다 별도 상관행렬을 만든다. 그림 3은 그 개별 검사들의 요약이며 하나의 개선된 전역 연결 결과가 아니다. 반복은 제거 대상 선택의 반복이고 독립된 SAE 학습 5회의 반복이 아니다. 현재 그림에는 학습 시드 간 변동이나 표본 재추출 신뢰구간이 없다.

그림 3의 점수 평균은 세 조건에서 두 상대의 상관이 모두 정의되는 공통 사례·반복으로 비교한다. 사용한 수와 전체 수를 그림에 표시하며 조건별 미정의 수와 제외 목록을 `/mnt/working/mm-sae/runs/elice-rq1/rq1/experiment3/paired_score_summary.json`에 저장한다. 점수가 미정의가 된 사례를 0점으로 채우거나 조건별로 다른 사례의 평균을 연결하지 않는다. 회복률과 손상률은 이 점수용 제외를 적용하지 않고 검사 가능한 전체 사례를 사용한다.

**논문용 확증 실험으로 승인하기 전에 다음 세 판단이 필요하다.** 현재 코드를 실행할 수 있다는 사실과, 그 결과로 원하는 논문 주장을 할 수 있다는 판단은 다르다.

1. 현재 안은 자동 캡션 주석과 최대 AUROC 대표를 사용한 진단이다. 이 결과를 사람의 의미 정답에 대한 정확도라고 부를 수 없다. 논문에서 의미 대응의 정확성을 주장하려면 캡션 주석과 대표 해석의 검수 범위를 먼저 정해야 한다. 현재 설정 그대로 전체 자료를 계산한다면 탐색적 진단으로 해석하는 것이 맞다.
2. 현재 무작위 대조는 동일 객체의 제거 양을 맞춘다. 목표 객체를 남긴 채 같은 모양의 다른 영역을 흰색으로 가리는 대조는 구현하지 않았다. 따라서 흰색 흔적과 순수한 의미 제거의 효과를 완전히 분리한 결론은 낼 수 없다. 그 강한 결론이 필요하면 대조를 추가한 설정을 다시 확인해야 한다.
3. 대표 선택과 상관 계산 모두 학습 자료를 쓴다. 그림 1은 점수와 동시 등장의 관계를, 그림 2는 대표들의 실제 연결을, 그림 3은 개별 오류의 제거 반응을 평가한다. 이 범위가 이번 RQ1의 주장인지 확인해야 한다. 새로운 이미지의 전체 특징 대응 정확도까지 주장하려면 별도의 평가 설계가 필요하다.

**서버 준비와 검사만으로 전체 소요 시간을 확정할 수는 없다.** 서버 GPU는 A100 전체 80GB가 아니라 10GB로 분할된 한 장이며, PyTorch가 보고한 사용 가능 장치 메모리는 약 9.5GiB다. 현재 단계, 처리 수, 총수, 경과 시간, 관측 속도로 계산한 단계별 예상 남은 시간을 10초마다 `/mnt/working/mm-sae/runs/elice-rq1/progress.json`에 저장한다. 아직 처리하지 않은 단계의 소요 시간은 미산정으로 남긴다. 전체 단계 중 몇 개가 끝났는지는 표시하지만 이를 시간 기준 진행률로 부르지 않는다.

승인 전에는 정적 검사, 단위 검사, 인공 자료 동작 검사와 서버 환경 확인만 진행한다. 기존 실제 COCO 소규모 실행은 이미지 6장과 캡션 30개로 실행 경로를 확인한 것이며, 그 실행에는 판정 가능한 제거 후 회복 사례가 없었다. 전체 자료의 대표 품질, 오류 수, 회복률은 아직 측정하지 않았다.
